# Audit et refonte Biogy — 24 septembre 2026

## Périmètre et méthode

Audit du site public, du dépôt GitHub et du code local. Essais fonctionnels dans Chromium avec Playwright, comptes et copies fictifs sur MongoDB éphémère. Aucune donnée d’élève réelle utilisée ou modifiée pendant les tests. Le style existant (vert, encre et titres sérif) est conservé.

## Améliorations réalisées

- Accueil, parcours Apprendre/Réviser/Laboratoire, connexion et aide réorganisés ; navigation mobile, accès clavier, focus, page introuvable, titres des pages et impression des cours.
- Recherche dans le texte intégral des cours avec filtres, favoris, reprise de lecture, repères « cours revu » et cartes de révision issues des contenus existants.
- Brouillons de TP conservés, export fidèle des listes et champs, envoi avec délai maximal, reçus et commentaires du professeur dans « Mes copies ».
- Corrections AT5 retirées de la page publique et protégées par le serveur. Nettoyage des copies HTML reçues, isolation de leur aperçu, protections contre les événements/scripts injectés, réinitialisation des comptes avec révocation des anciennes sessions.
- Connexion adaptée aux identifiants français ; limitation des tentatives tenant compte du réseau partagé d’une classe. Erreurs utiles quand MongoDB ne répond pas.
- Recherche forum déclenchée à la demande, filtres de veille synchronisés, requêtes obsolètes ignorées sur les principaux écrans.
- Remplacement de Create React App par Vite, suppression des dépendances inutilisées et des 1 461 fichiers de dépendances serveur suivis dans Git. Versions verrouillées, Node 22 et vérifications GitHub Actions.
- Quatre médias de cours convertis en WebP : 6 834 962 → 4 477 902 octets (−34 %). Les trois planches PNG sont converties sans perte ; les originaux sont conservés dans le dépôt.

## Validation locale

- 7 tests frontend et 18 tests serveur réussis, compilation de production réussie.
- Audits npm des dépendances de production : aucune vulnérabilité signalée pour le frontend, le backend et les fonctions Netlify au moment de la vérification.
- 15 routes publiques parcourues sans exception JavaScript : accueil, catalogue, niveaux, cours, révisions, laboratoire, séance, actualités, forum, projets, connexion, inscription, aide et page introuvable.
- Contrôle des débordements horizontaux sur neuf écrans représentatifs à 320, 390, 768, 1024 et 1440 px : aucun débordement détecté.
- Audit automatisé axe WCAG A/AA : contrastes des boutons et textes secondaires corrigés, champs du TP nommés. Ce contrôle automatisé ne constitue pas une certification d’accessibilité.
- Favoris, cours revu et onglet Bilan conservés après rechargement. Recherche « microscope » dans le contenu, cartes de révision et compteur d’autoévaluation vérifiés.
- TP : restauration du brouillon, sélection conservée, téléchargement, envoi, copie reçue en administration, retour enregistré et visible par l’élève. Accès aux 15 blocs professeur autorisé pour le professeur, refusé pour l’élève.
- Inscription avec identifiant accentué, création et lecture d’un sujet du forum, profil et isolation des copies d’un second élève vérifiés dans le navigateur.
- Mot de passe : réinitialisation par le professeur, connexion temporaire, changement obligatoire puis retour vers les copies validés dans le navigateur.
- Tests serveur dédiés : compte privé, droits admin, isolation des reçus entre élèves, HTML dangereux, rôle demandé à l’inscription, mode dégradé sans base.

## Hébergement et limites

Au début de l’audit, le serveur Render était vivant mais sa base MongoDB ne se connectait pas (`database: connecting`). Les comptes, les discussions et les copies du site public dépendent de cette connexion. Les essais locaux prouvent le fonctionnement du code avec une base disponible, pas celui du cluster de production.

L’accès Render a ensuite été obtenu. Ses journaux confirment une erreur DNS MongoDB `querySrv ENOTFOUND` : l’adresse du cluster configuré ne se résout plus. Cela peut correspondre à un cluster suspendu ou supprimé, ou à une adresse devenue obsolète ; seul Atlas permet de trancher. L’onglet Atlas attend la connexion du propriétaire. Aucun secret n’a été ajouté au dépôt et aucune migration destructive n’a été exécutée.

La commande de construction du service Render existant a été corrigée de `yarn` vers `npm ci`. Un fichier `backend/.node-version` impose Node 22 dans le sous-dossier effectivement utilisé par Render. Déploiement `c4f36de` confirmé « Deploy succeeded | Live », sous Node 22.23.3 ; démarrage existant `yarn start` fonctionnel. La panne DNS MongoDB subsiste indépendamment de ce déploiement.

La [PR #1](https://github.com/Paradoxollie/Biogy/pull/1) est fusionnée. GitHub Actions et les aperçus Netlify/Vercel sont réussis. Le site https://biogy.netlify.app a été vérifié après publication : nouvel accueil, cartes de révision, 15 emplacements de corrigé vides dans le TP public et veille RSS HTTP 200. Aucun échec axe sur l’accueil publié, y compris son message de service indisponible ; aucune exception JavaScript sur ce parcours public.

Le contenu pédagogique existant a été conservé. Plusieurs chapitres, notamment en Terminale, restent à rédiger par l’enseignante. Les corrections automatiques du TP restent des aides sur les calculs et réponses fermées ; elles ne remplacent pas une validation pédagogique. Le fonctionnement des envois d’images Cloudinary en production nécessite également des identifiants d’hébergement valides.
